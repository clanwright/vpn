# NaiveProxy: серверный аудит на 7 сентября 2026

## Доработка кандидата от 8 сентября

Ниже сохранён исходный снимок аудита. По последующему решению владельца
реализована штатная схема `sops.templates` + Caddy reload. Собственные
generator/refresh units, staging и общий rollback отменены. Пароли теперь
имеют согласованный контракт машинно генерируемых base64url-строк без пробелов
и terminal LF; произвольные строки не интерполируются как поддерживаемый ввод.
Генерация и проверка соответствия реальных secret inputs остаются у consumer.

Кандидат добавляет карту device identities с отдельным probe, public-site
assertions, scoped CONNECT routes, явные destination ACL и все публичные TCP
порты. `additionalDeny` принимает только IP/CIDR. Caddy autosave конфигурации
отключается, чтобы новые runtime credentials не сохранялись на постоянный диск.
Удаление ранее созданного autosave не выполняется автоматически.

Caddy 2.11.4 и forwardproxy `d62c80d3dd2c` сохраняются как единственное
согласованное исключение из stock-package policy. Точный Network output не
найден в четырёх проверенных кэшах; сборка в этом проходе не выполняется.
Standalone NaiveProxy wrapper удалён: runtime-потребителя в проекте нет.
Sing-box 1.14.0 и Cronet берутся штатными пакетами nixpkgs с точными outputs
в cache.nixos.org. Клиентский профиль отклоняет весь UDP защищаемых
направлений и не предлагает DIRECT в Naive selector. Если устройству не доступен
ни один Naive endpoint, sing-box-профиль, его handler и ссылка не публикуются.

Текущая приёмка — pure Nix и статическая гигиена. VM, Python, application
parser/CLI, runtime tests и тесты на реальных машинах запрещены. Прежние
результаты parser/build не являются результатом нового gate. Полный pure Nix
gate прошёл; итоговая репозиторная приёмка зафиксирована в
[основном аудите](audit-2026-09.md). Прикладная доступность и реальный Caddy reload не
объявляются проверенными. Релиз, deployment, реальные secrets и испытания на
операторах не выполняются. Текущий контракт — в module README,
границы приёмки — в [runbook](operations/naiveproxy.md).

## Исторический снимок до доработки

Исследование и рекомендации для обсуждения. Реализация, обновление пакетов,
активация, изменения DNS/ACME и секретов не разрешены и не выполнялись.
Сохраняется согласованное разделение: Naive-клиент в sing-box, серверная
архитектура выбирается без ограничений старых клиентов.

## Что есть сейчас

База — `06b5652b932a9779931088626c60279618850505`.
[Модуль Naive](../clanServices/naiveproxy/default.nix) добавляет runtime
`forward_proxy` fragment к существующему Caddy public-site claim. Это сервер
Caddy с Naive-совместимым forwardproxy, а не серверный процесс Chromium.
Прежний standalone пакет NaiveProxy с номером 150 не являлся версией
работающего серверного обработчика и удалён как неиспользуемый wrapper.

| Область | Текущее состояние | Оценка |
|---|---|---|
| Transport | Экспорт TCP/443; клиент HTTPS/H2, `quic=false` | Подходящая основа отдельного TCP-пути |
| Auth | Три жестко заданных identity: два пользовательских и probe | Есть отдельный probe, но нет индивидуального отзыва по устройствам |
| Маскировка | `probe_resistance`, `hide_ip`, `hide_via` | Сохранить; реальное поведение сайта при неверной auth еще проверить |
| Destination ports | Только `80 443` | Ограничивает TCP-приложения вне web-портов |
| Destination ACL | Собственные правила отсутствуют | Полагаться на upstream defaults как на полную защиту внутренних сетей нельзя |
| Credentials | SOPS `0400`, fragment в `/run` с `0640 root:caddy` | Верная граница хранения; содержимое остается секретным |
| Renderer | Пароль подставляется через `%s` без Caddyfile escaping | Пробелы, кавычки и служебные последовательности могут изменить разбор |
| Lifecycle | Генератор требуется для Caddy; смена секрета перезапускает Caddy | Связь с доступностью всех сайтов этого процесса |
| Проверки | Контракт/export/наличие unit | Полная конфигурация Caddy и прикладной CONNECT не приняты live-тестом |

`machineName` используется в shell и путях, но проверяется лишь на непустоту.
Нужен ограниченный формат идентификатора и корректное quoting всех применений.
Чтение пароля сейчас удаляет все LF: следует определить однострочный secret
contract и отклонять недопустимый ввод, а не молча преобразовывать credentials.

## Один рекомендуемый серверный вариант

Сохраняем **Caddy + Naive fork klzgrad/forwardproxy, прямой HTTPS/H2** на
существующем public-site endpoint. Не добавляем промежуточный proxy/CDN,
отдельный сервер sing-box или произвольные transport headers.
Это реализация из [официальной инструкции Naive](https://github.com/klzgrad/naiveproxy/blob/v150.0.7871.63-1/README.md),
в которой fork добавляет необходимый padding к обычному forwardproxy.

| Параметр | Целевой выбор |
|---|---|
| Caddy | `2.11.4`, точная сборка владельца Network |
| forwardproxy | Сохранить `d62c80d3dd2c`: это commit текущего `v2.11.2-naive` |
| TLS | Доверенный сертификат имени endpoint, штатные современные настройки Caddy |
| Listener | Существующий согласованный bind TCP/443; catch-all route нужен для CONNECT к разным origin |
| HTTP | H2 для Naive, обычный HTTPS-сайт; не менять глобально протоколы остальных Caddy sites |
| Auth | Непустые случайные credentials на устройство и отдельный probe; только runtime |
| Probe resistance | Включена, без дополнительного secret-link/PAC endpoint |
| Forwarded/Via | `hide_ip` и `hide_via` включены |
| Cover site | Настоящий доступный статический сайт, обычные ответы и compression для контента |
| Padding | Штатный Naive padding, без ручных изменений его размеров |
| Timeouts/pools | Штатные; не переносить клиентский concurrency или настройки Go HTTP pool в «анти-ТСПУ» рецепт |
| Upstream chaining | Отсутствует |

Версии проверены по релизам [Caddy](https://github.com/caddyserver/caddy/releases/tag/v2.11.4)
и [forwardproxy](https://github.com/klzgrad/forwardproxy/releases/tag/v2.11.2-naive).
Прежняя оценка «plugin устарел» снята: майский релиз указывает на тот же
январский commit. Дата релиза бинарной сборки и дата исходников различаются.
В tagged `go.mod` указан Caddy 2.8.4; это не доказательство несовместимости
с 2.11.4, но итоговая сборка и runtime-приемка требуют проверки.
В этом проходе исходник Network pin повторно не получен из-за недоступного
Nix daemon; локальные версии Network взяты из ранее составленного аудита. Номер релиза готового upstream Caddy+plugin artifact не требует
понижать Caddy до 2.11.2: нужны отдельно закрепленные host и plugin.
Текущий [Naive client 150.0.7871.63-1](https://github.com/klzgrad/naiveproxy/releases/tag/v150.0.7871.63-1)
уже соответствует проверенному latest; обновление его не обновляет Caddy plugin.

## Область доступа: принятое решение

Пользователь согласовал все TCP destination ports публичного интернета для
авторизованных устройств с запретом внутренних адресов. Сейчас реализованы
только 80/443; принято решение, но реализация и активация не разрешены.
Это исходящие назначения CONNECT, а не открытие дополнительных входящих
портов VPS. Разрешения провайдера и сетевые ограничения не исчезают.

Для выбранной области доступа нужна явная ACL: запрет внутренних, loopback,
link-local/metadata и tailnet адресов перед разрешениями публичного интернета.
В точном upstream теге штатные deny охватывают RFC1918, IPv4/IPv6 loopback
и IPv6 link-local, но не `169.254.0.0/16`, `100.64.0.0/10` и `fc00::/7`.
Нужно дополнить их и учесть локальные/служебные адреса конкретной машины,
включая доступные по публичным IP административные endpoints. Не ставить
широкий `allow all` перед deny: пользовательские правила идут раньше defaults.
Источник: [точный forwardproxy.go](https://github.com/klzgrad/forwardproxy/blob/v2.11.2-naive/forwardproxy.go).

Не добавляем hostname allow, способные обойти последующие IP deny.
Обработчик собственного сайта имеет особое поведение, поэтому проверяем его
отдельно от проксирования к назначениям. Для обычных proxy destinations
политика применяется к IP после разрешения имени; приемка должна включать
literal IP и имя, разрешающееся во внутренний адрес. Это не заменяет firewall
и права доступа самих внутренних сервисов. Системный resolver Caddy и его
зависимости определяет consumer; addon не должен молча переназначать DNS.

## UDP и клиентские параметры

В точном Caddy forwardproxy теге dialer поддерживает только TCP; Naive
UDP relay/CONNECT-UDP не реализован. Поле sing-box `udp_over_tcp` — отдельное
расширение, которому нужен совместимый backend; выбранный Caddy им не является. Не объявляем этот
Naive endpoint универсальным TCP+UDP VPN и не включаем поле на основании
одного клиентского parser check. Переход outer transport на QUIC также
сам по себе не добавляет relay произвольных UDP-приложений.
Основание: [sing-box Naive outbound](https://sing-box.sagernet.org/configuration/outbound/naive/).

Клиентскую настройку `insecure_concurrency=0` сохраняем как исходную:
upstream предупреждает о заметности нескольких параллельных туннелей.
Увеличение окна/числа соединений без измерений не является серверным улучшением.
Пользователь принял ограничение TCP-only Naive: UDP, направленный политикой
в Naive, блокируется без скрытого DIRECT или автоматической смены ручного
выбора. Для приложений, которым нужен UDP, пользователь вручную выбирает
другой поддерживающий его протокол. Это относится и к full mode; прямые
исключения LAN/router/Tailscale сохраняются согласно общей политике.
Решение пока не реализовано и требует проверки клиентского поведения.

## Что исправить при будущем внедрении

1. Проверить фактический состав итогового Caddy в Network и зависимости сборки;
   смена plugin commit ради существующего release tag не нужна.
2. Сделать безопасную сериализацию credentials, строгие имена и однострочный
   secret contract. Проверить спецсимволы на фиктивных данных; не печатать
   адаптированный JSON или ошибки с реальными credentials.
3. Валидировать полный composed Caddy config до замены; атомарно публиковать
   fragment, удалять временный файл также при ошибке, сохранять последний рабочий.
4. Добавить в addon явную проверку `selectedClaim.publicSite = true`: сейчас
   его собственные assertions не обеспечивают это требование README.
   Проверить порядок handler, catch-all и пересечения listeners: CONNECT
   не должен появляться на дополнительных tailnet-only listeners или HTTP/80.
5. Согласовать обновление credentials через штатный graceful reload, где это
   позволяет Network lifecycle, чтобы не перезапускать все сайты без необходимости.

Логи не отключаем глобально по примеру upstream: эксплуатационная диагностика
нужна. Исключаем credentials и auth headers; не включаем body/debug dumps.
Согласованные 7 дней относятся к DNS query log и не задают автоматически
срок всех журналов Caddy. Политику журналов и Caddy admin API хранит consumer.

## Доказательство работоспособности

Нужны: корректный TLS/SNI и H2; обычный сайт без credentials; отсутствие
proxy-auth challenge/доступа к target при неверных credentials; реальный
Naive handshake с padding; длительные upload/download; отказ private/metadata
назначениям по IP и DNS; проверка разрешенных/запрещенных портов; reconnect
после idle и reload. Проверки общего Caddy включают остальные сайты и listeners.

Исходники и интернет-источники проверены 7 сентября 2026, живые серверы не
проверялись. Нет контролируемого сентябрьского испытания этого профиля на
Дом.ру, Т-Мобайл и Yota. Поддержка upstream не доказывает обход фильтрации
IP/ASN или доступность в мобильном allowlist.
